# 今天吃什么 · 打开即随机

面向不知道午餐吃什么的用户，先随机给一个餐品方向，再匹配附近真实餐厅。线上地址：https://vermillion-cannoli-affefd.netlify.app/

## 本地运行

Node.js 22.13+（推荐24）。`npm install` → `npm run build` → `npm start`，访问 http://localhost:3000 。也可双击 `start-local.cmd`。开发使用 `npm run dev`。

## 本次产品逻辑

- 不填偏好、不授权定位也能换午餐灵感；初始建议不冒充已核实的附近推荐。
- 设置位置后只展示数据源返回的真实商家，不再插入示例餐厅，不生成无菜单依据的招牌菜。
- 换个吃的更换品类；这个想吃、换家店保留品类。同一轮店铺不重复，耗尽后主动重新开始。
- 预算分期望值与严格参考人均上限；严格模式中未知价格不会被当作预算内。参考人均不是最终账单承诺。
- 营业判断考虑估算步行、等餐和堂食余量；临近闭餐和已休息商家从主推荐排除。出发前再次检查时效。
- 支持常见的每日、多时段、按星期与跨午夜营业表达；复杂节假日/日期例外或过期信息保守显示待核实。厨房最后接单时间没有数据，不能保证接单。
- 天气独立查询，不阻塞餐饮结果。请求超时、定位拒绝、条件无匹配均有重试/地图出口。
- 手账沿用原 localStorage 键 `shifanfou.journal.v1`，原记录不迁移、不覆盖。记录仅当前浏览器可见。

## 数据服务与边界

默认使用 OpenStreetMap Overpass 查询真实餐饮；营业时段有则读取，价格没有则显示未知。国内覆盖和信息完整度有限。天气与城市参考点来自 Open-Meteo，城市搜索结果必须用户确认，不当作精确位置。

可选：在 Netlify 的 Environment variables 添加服务端变量 `AMAP_WEB_KEY`，启用高德 Web 服务地点搜索、周边餐饮、参考人均与今日时段。Key 不能使用 `NEXT_PUBLIC_` 前缀、不能提交到 GitHub。需自行确认所申请 Key 的接口权限、使用许可及额度；本仓库不包含 Key，也不自动开通付费服务。配置后重新部署。

高德数据接入代码已准备，但没有密钥的环境未进行真实高德请求验证。高德商家可能缺少价格或时段，仍会显示未知。GPS 坐标经高德转换接口转为 GCJ-02，高德搜索点及商家点保持其原坐标体系；跳转地图时显式指定坐标类型。

外卖未接入配送范围、实时接单、库存及订单接口，不把支持外带当作可配送。界面提供平台核实出口；堂食与打包是当前完整匹配路径。仅有餐厅品类时推荐类别，不承诺具体菜品或过敏安全。

营业提示基于公开时段估算，不能称为商家实时状态；当没有时区、时段、价格或最新数据时不作正向确认。取餐预计时间与路线时间并非实时服务商承诺。

## 部署与验证

仓库保留 `netlify.toml` 和 `vercel.json`，Netlify 连接 main 自动发布。构建 `pnpm run build`，发布目录 `.next`，无需数据库。保留生产域名可保留浏览器手账；更换域名不会自动转移浏览器数据。

`npm test` 覆盖闭餐、午间分段、跨午夜、复杂/过期时段、预算、配送未知、品类避开与候选去重。`npm run build` 完成类型与生产构建。`/api/version` 可核对线上应用版本与部署提交。
